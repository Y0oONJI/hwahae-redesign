# 화해 리디자인 프로토타입

화해(Hwahae) 앱의 홈 · 검색 · 결과 · 상세 · 성분 화면을 다시 설계한 인터랙티브 프로토타입입니다.
의존성 없는 단일 HTML 파일이며, iPhone 14(390 × 844pt) 기준으로 만들었습니다.

## 실행

```bash
# 그냥 열기
open index.html

# 또는 로컬 서버 (VSCode Live Preview / Simple Browser 용)
python3 -m http.server 8765
# → http://localhost:8765/index.html
```

## 화면

| 화면 | 진입 경로 |
|---|---|
| 홈 | 시작 화면 |
| 검색 | 홈 검색창 탭 |
| 결과 — 카테고리 / 제품 / 성분 | 자동완성 제안 또는 인기 검색어 |
| 제품 상세 | 리스트의 제품 행·카드 |
| 성분 | 상세의 궁합 카드 또는 성분 링크 |
| 성분 사전 | 홈 퀵메뉴 · 하단 탭 카테고리 |
| 찜한 제품 | 홈의 찜 궁합 알림 |

## 설계의 핵심

**모드를 먼저 고르게 하지 않는다.** 원본은 검색 진입 시 `통합검색 / 성분검색` 중 하나를 강제했습니다.
두 모드의 범위가 겹치고, 입력을 시작하면 토글이 사라져 확인도 변경도 불가능했습니다.
여기서는 입력창 하나로 통합하고, 분기를 **검색 뒤(결과 탭)** 로 옮겼습니다.

**성분을 "가서 봐야 하는 것"에서 "이미 보이는 것"으로.**

- 리스트 행마다 `내 피부 92점` 궁합 칩 — 상세에 들어가기 전에 판단
- 결과 화면 필터 바에 `내 성분 빼기` 상시 노출 (원본은 3단계 아래)
- 상세 상단에 궁합 카드, 성분 페이지는 결론 → 근거 → 원자료 3층
- 홈 퍼소나 카드에서 마이 성분을 직접 담고 뺌

**하나의 마이 성분이 모든 화면에서 돈다.** 어디서 성분을 담거나 빼도
홈 퍼소나 · 검색 폼 · 리스트 점수 · 상세 궁합 · 성분 페이지 · 찜 목록이 동시에 반응합니다.

**조건으로 찾기.** 항공·숙박 앱의 파라메트릭 검색을 가져오되 강제하지 않습니다.
`카테고리 + 성분(넣기/빼기)` 두 슬롯이 프로필 값으로 미리 채워져 있고,
조건을 만질 때마다 버튼의 예상 결과 수가 실시간으로 바뀝니다.

## 구조

```
index.html    단일 파일 (HTML + CSS + JS 인라인, 외부 의존성 없음)
```

- 화면은 `<section class="screen" data-screen="...">`, 전환은 `data-go="<screen>"` 위임 클릭
- 마이 성분 상태는 `my` 배열 하나, `renderIng()`가 전 화면을 다시 그림
- 아이콘은 인라인 SVG 스프라이트, 제품 이미지는 CSS/SVG 목업
- 한글은 iOS 시스템 폰트(`Apple SD Gothic Neo`) 스택 사용

## 알아둘 것

수치(점수·건수·리뷰 수)는 구조를 보여주기 위한 **더미 데이터**입니다.
실제 궁합 점수 산식이나 성분 데이터가 아닙니다.
